# 导出剪映分轨草稿

成片定版后，额外导出一份剪映草稿，用户可以在剪映里继续：改美颜、逐条改字幕、增删音效、调配乐音量。**画面和成片一致**。

## 六条轨道

| 轨道 | 内容 | 用户能改什么 |
|---|---|---|
| 口播 | `口播_无美颜.mp4`（只调色，**静音**）+ 位置 / 缩放关键帧，分屏让位和推镜跟成片一致 | 在剪映里加美颜；想用成片同款，换成 `口播_已美颜.mp4` |
| 人声 | `人声.wav`（处理后的人声，增益与成片一致），**独立音频轨** | 调音量、降噪 |
| 包装 | `包装层.mov`：透明底 ProRes 4444，包含卡片、截图、B-roll、转场、进度条，不含口播和字幕 | 一般不动 |
| 字幕 | 剪映原生文字（得意黑 + 黑色半透明底条），一句一个片段 | 逐条改字、改样式 |
| 音效 | 每个音效一个片段，音量已含统一增益；时间上重叠的会自动分到相邻音频轨 | 删、挪、换 |
| 音乐 | 配乐分轨（已按人声压低） | 整条调音量 |

人声、配乐、音效乘同一个增益导出，叠加后 -16 LUFS，与成片一致。

## 需要的功能和资源（导出前逐项确认，`check_env.py <P>` 会自动检查）

| 需要什么 | 为什么 | 怎么准备 |
|---|---|---|
| **剪映专业版 Mac** | 本 skill 写的是剪映 Mac 版的明文草稿（`draft_info.json`），只在 11.x 上验证过 | 安装剪映专业版。Windows 版和更新版本的格式可能不同，出问题看文末"已知风险" |
| **外壳草稿** | 剪映草稿文件夹里除了 `draft_info.json`，还有一堆元数据文件，只能从一个真实草稿克隆。**本仓库不附带，因为它含有剪映账号和设备数据** | 在剪映里新建一个空草稿 → 退出剪映 → 运行 `python3 scripts/setup.py --jianying-shell <该草稿文件夹>`（写进共享配置，所有项目通用） |
| **剪映字库里的得意黑** | 原生字幕要引用剪映缓存里的字体文件，否则会回退成默认字体 | 在剪映里给任意文字选一次"得意黑"，让它下载到缓存。资源 ID 默认 `7399865900821647935`（共享配置 `jianying.font_resource_id`） |
| **磁盘空间** | 包装层是 ProRes 4444 带透明通道，**约 2.5 GB / 分钟**（3 分钟片约 7 GB） | `python3 scripts/setup.py --media-dir <空间够的盘>`，每个项目会在下面自动建子文件夹。外接盘也可以，但打开草稿时要插着 |
| **剪映处于退出状态** | 登记草稿要改剪映的草稿列表 `root_meta_info.json`，剪映运行时改了会被覆盖 | 完全退出剪映再执行 `jianying.py`；脚本修改前会自动备份草稿列表 |
| **Python + playwright + ffmpeg（prores_ks）** | 渲染包装层、导出分轨 | 和成片流程用的是同一套环境 |

## 步骤

```bash
E=scripts/engine; M=$(python3 $E/proj.py <P>)              # 这个项目的剪映素材目录（规则见下）
python3 $E/render.py <P> overlay 0 <时长> $M/包装层.mov 5   # 透明底包装层（自动清理半透明抖动像素）
python3 $E/render.py <P> akeys                             # 每帧口播位移/缩放 → work/aroll_motion.json
python3 $E/stems.py <P>                                    # 人声 / 配乐 / 音效分轨 + 每个音效的音量
python3 $E/export_aroll.py <P>                             # 口播_无美颜.mp4 / 口播_已美颜.mp4（文件里带人声，但草稿里静音，人声走独立轨）
python3 $E/jianying.py <P> <草稿名>                         # 生成草稿并登记；加 --beauty 用已美颜版，--no-register 只生成不登记
```

完成后打开剪映，草稿列表里就能看到。

**素材目录每个项目独立**（`proj.py` 的 `Project.jianying_media`）：
- `project.json` 写了 `jianying.media_dir`：原样使用。
- 只有全局 `config.json` 写了 `media_dir`：使用 `<全局目录>/<项目文件夹名>/`。
- 两边都没写：使用 `<项目>/output/jianying_media/`。

素材文件名是固定的（`包装层.mov`、`人声.wav` 等）。如果多个项目共用一个目录，后一个项目会覆盖前一个的素材，前一个项目的草稿就坏了。

## 修改后再出草稿：默认更新现有草稿

**默认在现有草稿上返修**，减少版本混乱；如果用户要求保留旧版或另建版本，则按要求处理。分两种情况：

1. **只改了画面或声音内容**（包装层、口播、人声、配乐、音效有变化，轨道和字幕没变）：重新导出到同一个 media_dir，**原地替换同名文件**，旧文件挪到 `_旧版/` 备份。草稿文件不动，所以剪映开着、草稿打开着都可以。剪映里重新打开草稿（或者跳一下时间线）就能看到新素材。这是最常见的返修方式。
2. **草稿结构变了**（字幕文字或样式、轨道增减、关键帧、画布尺寸）：`jianying.py <P> <第一版草稿名>` 会**原地重写第一版**。它先把 draft_info.json、Timelines 副本、draft_meta_info.json、crypto_key_store.dat 备份到 `<草稿>/.tthe_backup/<时间>/`，移走密钥，再写回明文草稿（剪映打开过的草稿会被加密，用明文覆盖即可）。这一步不动草稿列表，**不用退出剪映**。如果剪映里正打开着这个草稿，请用户先回到首页，写完再打开，免得剪映保存时把新内容覆盖回去。
   - 原地重写会覆盖用户在剪映里的手动修改（美颜、改字、调音量）。用户说过自己改过时，先问再重写。
   - `--new` 只在用户明确要求另建一版时使用。

## 坐标与关键帧

- 剪映的归一化坐标：`x = 像素偏移 / 960`，`y = -像素偏移 / 540`（向上为正）。
- 成片里口播以画面高度 42% 处为原点缩放，剪映以中心缩放，所以每个关键帧都补了竖直位移 `(540 - 453.6) × (s - 1)`。
- 关键帧只在发生变化的地方取点，线性插值。缓动段每 2 帧取一个点。

## 已知差异与风险

- **毛玻璃**：成片里卡片的背景模糊会糊掉身后的口播。分轨后包装层是透明底，拍不到身后的口播，所以叠在口播上的少数卡片会比成片更透一点。全屏场景完全一致。
- **音效轨数量**：时间上重叠的音效会分到 2–3 条音频轨。如果想要单轨，用同目录的 `音效_合并.wav` 替换。
- **剪映版本升级**：草稿格式可能变化。症状和对应原因：
  - 打不开 / 媒体丢失：先看 `jydraft.py` 里的模板字段。
  - 没声音：检查 `has_sound_separated`。
  - 字体不对：检查字体缓存路径。
- **剪映不认的东西**：本 skill 只写视频、文字、音频和关键帧，不写剪映特效、动画、滤镜，这些都已经渲染进包装层了。

## 踩过的坑（已在脚本里处理）

1. **打开草稿没有人声**：曾遇到剪映未能从脚本写入的视频素材中正常读取声音，即使相关字段看起来正确。**结论：不要让剪映从脚本写入的视频素材里取原声。** 现在 `jianying.py` 把口播视频静音（`volume=0`、`has_audio=False`），人声用 `人声.wav` 单独放「人声」音频轨。生成后核对：草稿里必须有一条名为「人声」的音频轨，且 `人声.wav` 的 mean_volume 不是静音。
2. **口播前出现一条竖向虚线**：Chrome 的透明截图在渐变淡出到全透明的位置有抖动，留下"几乎透明但颜色极亮"的像素。剪映合成时会把它们显示出来，浏览器和 ffmpeg 合成时看不出。现在 `render.py overlay` 会把 alpha < 24 的像素颜色按 alpha 比例压暗，可见内容不变（PSNR 45dB）。
