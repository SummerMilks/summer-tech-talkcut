# 剪辑规则

这些规则来自真实合作中的多轮反馈（v1 → v5）。没写进来的细节以"成片好看、观众看得懂"为准。

## 1. 粗剪

- **原片只读**：不改、不删、不移动。
- **转写**：用 whisper.cpp + large-v3-turbo，**不要开 VAD**（开了以后逐字时间会越来越偏）。拿到结果先自检：每句第一个字的时间和整句开始时间相差超过 1.5 秒，就说明时间轴有问题，停下来排查。
- **保留哪一遍**：同一句或同一段录了多遍时，只留**最后完整的一遍**。
- **要去掉的**：
  - 口误后重说
  - "重来""这段不要""中间空一下"
  - 和摄影师、旁人的讨论
  - 试音
  - 清嗓
- **切点**：按静音检测（ffmpeg silencedetect，-35dB / 0.25s）定。**不要用 Whisper 的逐字时间卡边界**，因为相邻字的时间首尾相连，切了会吃字。
- **气口**：段首留 0.12s，段尾留 0.22s。段内超过 0.65s 的停顿压到 0.38s。
- **复核（必须做）**：对粗剪结果重新转写，通读一遍，确认没有重复和半截话。Whisper 常把好几遍录音识别成一句长句，只看第一遍转写会漏掉。

## 2. 字幕

- **字体和样式**：得意黑（Smiley Sans，OFL），58px，白字，黑色 58% 半透明圆角底条，底部居中（底边距 62px）。
- **断句**：一屏一句，不超过约 16 个字；长句在逗号或语义处拆开。
- **内容**：按实际口播，不按原稿。口播临场改的词以口播为准。
- **常见错字**：同音错字集中在产品名、人名、英文术语，例如 Grok Bot、Claude Code、GPT-6 Astra。要**联网查证**再改。反例：v1 里口播的"Q"实际是 Manus 的 **Cue**，查了官方报道才确认。
- **拿不准的**：按原音保留，并在交付说明里列给用户确认，不要硬猜。
- **超出范围的比较说法**：口播里的"最低""最好"这类比较说法，字幕照录（字幕必须和声音一致），但**画面文字不要再写**。

## 3. 美颜与调色

- **美颜**：只在亮度通道做双边滤波（sigmaS=14, sigmaR=0.07），按 55% 混回原图，再轻提亮、轻锐化。效果是"皮肤干净、看不出开了美颜"，**不要过度**。强度由 project.json → beauty 控制。
- **调色**：对比度 ×1.05、饱和度 ×1.04，阴影偏冷，高光微暖。全片加颗粒和暗角。

## 4. 选画面：三原则（最高优先级）

每个分镜**先判断这段话属于哪类内容，再决定配什么画面**：

| 内容类型 | 画面 | 例子 |
|---|---|---|
| **新闻 / 产品信息**（发布、功能、价格、名单） | **官方素材优先**：官方演示视频、带真实任务场景的产品图，旁边配**中文注释**，说清画面里正在发生什么。其次是截图，只用来"证明存在"，比如中文报道标题、价格表这类一眼能看懂的 | Meta 官方演示里的"日本旅行 + 训练计划"，配中文注释；OpenAI 帮助中心价格表，高亮其中一行 |
| **抽象概念**（感受、场景、生活化例子） | 真实 B-roll，必要时多段蒙太奇，**不加字** | "找一个真实的日常需求，先用起来" → 三段生活 B-roll |
| **流程 / 规则 / 结构**（步骤、分层、构成、决策） | 流程图：节点、连线描线动画、依次点亮 | 时间线、分层图、中心辐射图、决策树 |

**多款产品并列**：章节页、总结页、对比页里同时出现几款产品时，用**产品官方 App 图标** + 产品名，不要用网页截图缩略图（缩成小卡片后什么都看不清）。图标用 `scripts/app_icon.py` 从 App Store 下载，并核对开发商是官方；没有独立 App 的产品，用官网的官方标识放进同样的圆角底。

**信息增量**：画面要给出口播之外的东西，比如具体例子、机制、时间、价格、官方原话（翻成中文）。

**自检**：每个场景都问一句，"去掉这个画面，观众少看到了什么？"答不上来就换。

## 5. 场景结构

- **按语义段落分场景**，一个重点配一个画面，整段话里元素随口播逐个出现。**不要逐句切换**。
- **口播出镜约占一半**。三种形式交替使用：
  - **全屏场景** `scene()`：产品发布、演示、流程图、价格、章节页、总结
  - **分屏** `split()`：人让到一侧（±330px），另一侧放内容。**左右交替**
  - **口播浮层** `overlay()`：点赞收藏、开场主题词，不打断人物
- **推镜**：全片极慢推近（1.00 → 1.06），关键句硬切推近（1.10–1.16）。
- **章节**：顶部放细进度条（例如：开场 / 是什么 / 怎么选 / 总结）；章节切换处配一个全屏章节页。

## 6. 动效与转场

- **所有元素都要有入场和出场**，不要出现静止贴图。
  - 入场：上浮、侧滑、弹出、虚化、缩放（outExpo / outBack，0.4–0.6s）
  - 出场：0.3s 淡出并加虚化
- **转场**：推镜虚化（zoom）、故障（glitch）、擦除（wipe）、闪白（flash），换着用。每个转场配对应音效。
- **截图卡**：先入场 → 缓推 → 描边高亮原文段落 → 四周压暗。
- **流程图**：连线用描线动画，节点按口播依次点亮。

## 7. 版式安全区（1920×1080）

- **字幕区**：y > 920 只留给字幕，其他元素的底边不超过 900。
- **人物**：原片人物居中，头部大约在 x 750–1300、y 80–500（推镜 1.1 时）。口播浮层的左边缘不小于 x=1300，或者放在左侧 x<700。
- **分屏**：人物让出 330px，面板宽 820，内容宽 740 以内。面板一侧加暗渐变垫底。
- **口播上的文字**：必须有暗渐变垫底，字号不小于 40px，否则压在杂乱背景上看不清。
- **卡片**：窗口或卡片入场时间最多比它的第一条内容早 0.5s，不要先出一个空框。全屏场景入场后 0.3s 内要有主体元素。

## 8. 音频

- **人声**：高通 75Hz、轻降噪、压缩（3:1）。
- **配乐**：科技向轻电子，在章节处换曲并交叉淡化；用侧链压低，有人声时自动让开；音量约比人声低 16 LU。
- **音效**：跟着转场和元素入场走。注意：
  - 小元素用 tick 或 pop，重点用 impact，转场用 whoosh、swipe、glitch。
  - **不要每个元素都响**。
- **整体响度**：-16 LUFS，真峰值 -1.5 dB。

## 9. 交付物

1. 成片 `output/<名>.mp4`：1080p30，H.264 CRF 15，AAC 256k。
2. `output/字幕与画面文字.txt`（扫描用）。
3. `output/交付说明.md`，包括：
   - 粗剪去掉了什么（附原片时间）
   - 字幕改了什么、待确认项
   - 口播事实核实表（说法 / 结果 / 依据）
   - 素材、截图和官方素材的来源与授权
   - 扫描结果，以及每条 REVIEW 的判断
   - 版本记录
4. （可选）剪映分轨草稿：见 jianying-export.md。
